# Internationalization (i18n)

The app ships in **English and Spanish**. Spanish is the primary language of the
foundation's staff and families, so "everything is translated" is a hard
requirement — enforced by a guardrail, not left to memory.

## Rules

1. **No hardcoded user-facing text.** Every string a user can see is
   `t("namespace.key")` (script) or `{{ t("namespace.key") }}` / `:label="t(…)"`
   (template). Keys live in **both** `i18n/locales/en.json` and
   `i18n/locales/es.json`.
2. **en / es parity.** A key must exist in both files, with no empty values.
3. **Spanish is human-authored.** No machine translation in the pipeline — write
   real Spanish (ask a Spanish speaker if unsure). This is deliberate.
4. **Namespace your keys.** Group by feature: `nav.*`, `common.*`,
   `contactForms.*`, `assign.*`, `patients.*`, `profile.*`, `schedule.*`,
   `calendar.*`, `sessionModal.*`, `employees.*`, `createAccount.*`, `contact.*`.
   Reuse `common.*` (`loadError`, `retry`, `yes`, `no`) for generic strings.

```vue
<script setup lang="ts">
const { t } = useI18n();
</script>
<template>
  <h1>{{ t("patients.title") }}</h1>
  <UInput :placeholder="t('patients.searchPlaceholder')" />
</template>
```

Interpolation: `t("assign.title", { role })` with `"title": "Assign {role}"`.

## The guardrail (`scripts/i18n-check.js`)

Runs in the **pre-commit hook** and `npm run checker`. Fails the commit when:

1. en/es key sets differ (a key in one, missing from the other)
2. any value is an empty string
3. a `$t("…")` key used in a `.vue` is undefined in the locales
4. a `.vue` template has **hardcoded UI text** not wrapped in `t()`

Run it anytime: `node scripts/i18n-check.js`.

### The ratchet (check #4)

New files must be i18n-clean. Legacy files that still hold hardcoded strings are
grandfathered on **`LEGACY_I18N_ALLOWLIST`** in the script. The list can only
_shrink_:

- A file on the list is skipped by the hardcoded-string check.
- When you migrate a grandfathered file to `t()`, the check **fails** until you
  remove it from `LEGACY_I18N_ALLOWLIST` — so you can't forget.
- When the list reaches **0**, every page is fully translated.

So the workflow when touching a legacy page:

1. Wrap its strings in `t()`, add the keys to `en.json` + `es.json`.
2. Delete its entry from `LEGACY_I18N_ALLOWLIST`.
3. `node scripts/i18n-check.js` should pass.

### Allowed hardcoded text

- **Brand / proper nouns** (`IGNORE_TEXT`): "Connected Care", "FMUA", the org
  email. Add to that set if you need another proper noun — don't translate it.
- **`pages/dev/`** — internal ADMIN/IT diagnostics tooling, intentionally
  English-only (permanent ignore).

## Language switcher

`components/LangSwitch.vue` (EN / ES). It's already in the app shells — use it,
don't hand-roll locale buttons. It takes a `vertical` prop for tight spaces
(the collapsed sidebar rail uses it).

Strategy is `no_prefix` (no `/es/…` URLs); the locale is stored client-side.
